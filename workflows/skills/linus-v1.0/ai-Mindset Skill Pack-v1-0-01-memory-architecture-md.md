# 01 · 长期记忆架构（B 档——一个月级长期记忆）

> **适用对象**：任务管理 AI 助手（网页版，minimax m3 模型，有文件调用能力）
> **目标**：让 AI 一个月后还能记得主人的偏好、决策、教训，不是金鱼脑。
> **核心**：分层存储 + 节奏化沉淀 + 上下文注入

---

## 一、心法：三句话

1. **记忆不是存档，是"陪跑员"的工作台** —— 不是数据库存字词，是连接主人的过去、现在、未来。
2. **没有沉淀的记忆 = 没发生过** —— 对话结束不写 memory，等于这次对话不存在。
3. **分层是为了不被打脸** —— 不同层级数据不同步，会出现"今早说的和昨天说的一致"这种最严重的错误。

---

## 二、四层记忆架构（B 档精简版）

```
Layer 1：核心层（IDENTITY.md）
  └─ 主人是谁、AI 是谁、关键词触发映射
  └─ 每次会话第一时间读，像知道自己名字

Layer 2：当前任务工作层（todo/projects/...）
  └─ 当前活跃项目的状态、决策、未完成项
  └─ 必须在每次回复前刷一遍（防失忆）

Layer 3：经验层（memory/YYYY-MM-DD.md）
  └─ 每天的对话精华、决策、教训
  └─ 3 天内全盘记录，4 天后固化进 MEMORY.md

Layer 4：开放层（MEMORY.md + 向量检索）
  └─ 跨月、跨项目的长期教训
  └─ 是前三层都查不到时的兜底
```

### 各层的"职责边界"

| 层           | 读   | 写      | 节奏     |
| ----------- | --- | ------ | ------ |
| Layer 1（核心） | 必读  | 主人定    | 几乎不变   |
| Layer 2（任务） | 必读  | 随时     | 每天更新   |
| Layer 3（每日） | 选读  | 每天必写   | 24h 内  |
| Layer 4（长期） | 选读  | 每周/月总结 | 30 天以上 |

---

## 三、节奏化沉淀（**最关键的执行纪律**）

### 每次对话结束 — 立刻沉淀

```bash
# 1. 提取这次对话的精华
精华 = 今天最重要的决策 + 教训 + 主人纠正

# 2. 写到当天 memory 文件
echo "## 2026-07-19" >> memory/2026-07-19.md
echo "精华内容..." >> memory/2026-07-19.md
```

**为什么必须立刻沉淀？**

- 当天写的 = 真实细节（具体命令、具体上下文）
- 一周后补的 = "那天大概聊了..."，模糊了
- 模糊了 = 等于白记

### 每天结束（cron 可触发）— 当天总结

- 把 3 天内的 daily memory 串成"今天学到了什么"
- 标记 🆕（3 天内）和 📅（7 天内）优先级

### 每周日 — 周复盘

- 选 3-5 条最值得长期记住的，写入 MEMORY.md
- 把过期内容从 MEMORY.md 删除

### 每月 — 月复盘

- 把 MEMORY.md 里过期的、错误的内容清理掉
- 重新组织成"我现在是什么水平 + 我学到了什么 + 我还得学什么"

---

## 四、上下文注入（**这是让 AI"接上话"的关键**）

每次主人发消息，**回复前的第一动作是构建上下文**：

```markdown
1. [必] 读 Layer 1 核心层（IDENTITY.md）—— 知道主人在和自己说啥
2. [必] 读 Layer 2 任务工作层（当前活跃项目）—— 知道上次聊到哪了
3. [选] 搜 Layer 3 最近 7 天 memory —— 知道最近主人有没有纠正过自己
4. [选] 搜 Layer 4 MEMORY.md + 向量检索 —— 知道主人的长期偏好
```

### 注入模板（写到对话开头）

```
[主人 message 来了]
↓
1. greet
2. 主动跑 read IDENTITY.md, read memory/今天.md, read memory/昨天.md
3. 读完后，回复开头先说"我读到了..."：
   - "我看到昨天你提到 XX，我接着那个继续..."
   - "你之前纠正过我要 YY，我先按 YY 处理"
```

## 五、防失忆的硬规矩

### 规矩 1：记忆执行不到位 = 没记忆

> **光有规则不等于执行**。血泪教训："规则写了不等于执行了 = 规则形同虚设"。
> 
> 解决：用**自动化脚本**强制执行沉淀，而不是靠记忆提醒自己。

```bash
# 示例：cron 每天 23:30 自动沉淀当天对话精华
30 23 * * * /path/to/daily_memory_precipitation.sh
```

### 规矩 2：3 天内的对话默认还记得，4 天后固化

- **3 天内**：原始对话可以查到 = 全盘记住
- **4-30 天**：写入 daily memory + 关键决策进 MEMORY.md
- **30 天+**：只在 MEMORY.md 留索引，详细内容进向量库

### 规矩 3：发现矛盾先验证，不猜测

> **主人的偏好是会变的**。今天说喜欢 X，明天可能说喜欢 Y。这不是矛盾，是成长。
> 
> 但**真正的矛盾**（同样场景下规则相反）= 必须问主人。

## 六、给你的具体操作建议（任务管理 AI）

```bash
# 项目目录结构建议
~/todo-agent/
├── IDENTITY.md          # Layer 1：你是谁，主人是谁
├── MEMORY.md            # Layer 4：跨项目的长期记忆
├── memory/
│   ├── 2026-07-19.md   # Layer 3：今天的对话精华
│   ├── 2026-07-18.md
│   └── ...
├── projects/
│   ├── project-A/
│   │   └── status.md   # Layer 2：当前任务进度
│   └── project-B/
└── data/                # 主人上传的文件
    └── ...
```

每次主人发消息：

1. 读取 `IDENTITY.md` + `MEMORY.md` + 最近 2 天 memory
2. 检索 `projects/` 看当前有什么活跃任务
3. 拼成上下文，开始回复
4. **回复结束前** → 把今天的精华写到 `memory/今天.md`

## 七、血泪教训（来自真实场景）

### 教训 1：主人说"b b b" 被误认成打错了

- 实际上"b b b"是某种格式的简写
- AI 没查上下文就问"打错了吗"——**这次对话直接失败**
- 修正：每次回复前必查上下文

### 教训 2：免费套餐耗尽 + 没有兜底 = 7 天失联

- AI 觉得"配置了 fallback 就够了"——结果 fallback 全军覆没
- 主人 9 小时没收到任何回复 = 严重的"AI 失语"
- 修正：**必须有外部独立告警**（邮件 / webhook），不依赖 AI 自己

### 教训 3：13 天沉默期 = 任务堆积

- AI 完成了 v4 大版本，但没主动汇报
- 主人主动问"任务如何了"才被发现
- 修正：**完成大任务后立刻汇报 + 主动沉淀**

---

## 八、检查清单（B 档合格线）

- [ ] 主人的核心信息（姓名 / 偏好 / 决策）能在 MEMORY.md 里查到
- [ ] 当天的对话精华，在 24h 内写入了 memory 文件
- [ ] 当前活跃项目状态，能在 projects/ 里查到
- [ ] 主人发消息时，前 1 分钟内已经把上下文拼好
- [ ] 主人纠正过的事，能被查到并执行
- [ ] 矛盾或不一致的规则，能主动识别并问主人

**如果以上 6 项有 3 项没做到 = 没真正记忆**。

---

**总结一句话**：记忆不是"我有一个文件夹存东西"，而是"我有一套机制确保：主人的过去决定我现在怎么做，现在的对话决定我下次怎么做"。
