# OpenClaw（龙虾）长期记忆改造方案

## 一、为什么龙虾记不住（核心原因）

- 上下文窗口硬限制：默认contextWindow/maxTokens偏小（常为4K–8K），几轮对话就触发压缩，旧信息被摘要或删除
- 记忆不自动持久化：对话只存在当前会话内存，重启/换新会话即清空；不会自动写入长期存储
- 压缩机制丢细节：定期compaction合并历史，细节丢失，只剩梗概
- 无结构化检索：纯文本存储，无法按语义精准召回，只能靠上下文碰运气

## 二、大模型长期记忆的核心逻辑

大模型长期记忆 = 短期上下文（工作记忆）+ 向量库（长期记忆）+ 摘要/结构化存储（核心记忆）

- 短期记忆：当前会话上下文（如32K–128K窗口），保证流畅对话
- 长期记忆（RAG）：向量数据库存储历史对话、用户偏好、关键决策，按语义检索注入上下文
- 核心记忆（结构化）：提炼身份、规则、偏好，每次启动必加载，优先级最高

## 三、四层架构改造方案

### 1. 底层：文件化永久存储（真相源）

- MEMORY.md（核心记忆）：存身份、核心规则、用户偏好、活跃项目、关键决策；每次启动自动加载
- memory/YYYY-MM-DD.md（日记，无限）：实时记录完整对话、决策、任务状态；Git版本控制
- evolution-log.md（进化日志）：记录技能学习、规则更新、重大调整

### 2. 检索层：向量+全文混合搜索

- 启用sqlite-vec（向量相似度）+ FTS5（全文搜索），构建内置RAG
- 对话时自动检索top-3相关历史记忆，注入当前上下文

### 3. 配置层：调大窗口+优化压缩

- contextWindow：设为模型最大支持（如128K）
- compaction: aggressive：只压缩非关键信息，保留核心规则/偏好

### 4. 自动化层：定时沉淀+冥想机制

- 每小时：自动Git提交日记
- 每日02:30：冥想——从当日日记提炼关键信息，更新MEMORY.md
- 每周日05:00：大整理——归档旧日记、优化向量索引、清理无效记忆

## 四、避坑要点

- MEMORY.md别写太满：只存永久不变的核心信息，超过10KB会被强制精简
- 向量模型要固定：频繁更换会导致向量漂移，旧记忆搜不到
- 关键指令显式写入：重要规则必须进MEMORY.md，不能只靠对话

## 五、效果对比

| 维度   | 默认配置        | 改造后          |
| ---- | ----------- | ------------ |
| 会话切换 | 完全失忆        | 记住偏好、规则、项目   |
| 重启后  | 重置记忆        | 核心记忆自动加载     |
| 长对话  | 10-20轮后压缩   | 100+轮仍保留关键信息 |
| 记忆容量 | 4K-8K token | 无限（文件+向量库）   |
